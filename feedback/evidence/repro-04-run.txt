6. Verdict
================================================================================================
lastUpdatedTimestampNs is 0 on ALL 21 live positions examined at block 28619406 (ours, 10 freshest, 10 oldest), spanning 0m 5s to 21d 6h since their last update.
The raw return has exactly 4 words matching the 4-field ABI, and the struct's third storage slot reads zero, so this is not a decoding artifact: no write to the field is observed on any sampled position (inferred: the contract has no code path that sets it).
In the shipped SDK, getPosition is the only position getter, this is its only timestamp field, and no position event carries a timestamp.
The SDK documents it as "Last position update (nanoseconds)", so a consumer relying on it silently receives 0. Not a security issue.
Limits: one pool (ETH-PERP), one block, one chain; "age" for the oldest group is the indexer's last-update time, not necessarily the position's creation or the contract version that wrote it; other pools were not checked.
